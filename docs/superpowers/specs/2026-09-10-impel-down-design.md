# Impel Down — 설계

2026-09-10. macOS에서 오락 사이트를 브라우저 불문 차단하는 개인용 도구.
사이트를 가두는 감옥이고, 시간표는 면회 시간이다.

## 목적

- 지정한 사이트·경로를 모든 브라우저에서 막는다.
- 묶음마다 요일·시간 단위로 열어두는 시간을 둘 수 있다. 비워두면 24시간 차단.
- 규칙은 앱 창에서 고친다. 설정 파일을 손으로 만지지 않는다.
- 차단은 백그라운드 엔진이 담당한다. 앱 창은 설정 도구이며, 앱을 꺼도 차단은 유지된다.
	- 별도의 끄기 스위치는 없다.

## 구성

- `app/` — SwiftUI 메뉴바 앱. 규칙 파일을 쓴다.
- `engine/` — mitmproxy 애드온(Python) + 설치·제거 스크립트 + launchd plist. 규칙 파일을 읽어 차단한다.
- 규칙 파일 `~/Library/Application Support/Impel Down/rules.json` — 앱과 엔진의 유일한 접점. 소켓·API 없음.

## UI

### 메뉴바 아이콘

- 메뉴바에 상주. 누르면 메인 창이 바로 열린다 (드롭다운 메뉴 없음).
- 로그인 시 자동 실행.

### 메인 창 — 묶음 카드

- 묶음 하나 = 카드 하나. 2열 격자.
- 카드 내용: 제목 · 주소 목록(그대로 나열) · 시간표 요약 · 상태 칩.
	- 상태 칩: 지금 닫혀 있으면 "차단", 열려 있으면 "열림 · HH:00까지". 앱이 규칙 파일과 시계로 계산한다.
	- 시간표 요약: 24시간 차단이면 "상시", 아니면 열린 요일·시간대를 짧게 (예: "토·일 20–23").
- 상단 "+ 묶음 추가" 버튼 → 새 묶음 시트.
- 카드 클릭 → 묶음 시트.

### 묶음 시트 (기존 묶음 편집 · 새 묶음 공용)

- 제목: 인라인 편집.
- 주소: 한 줄에 주소 하나. "+ 주소"로 줄 추가. 줄에 마우스를 올리면 ✕가 떠 그 줄을 지운다.
	- 붙여넣기 정리: `https://`·`http://`·앞의 `www.`·끝의 `/`·`?` 뒤 쿼리·`#` 뒤 조각을 떼고 호스트+경로만 남긴다. 호스트는 소문자.
- 시간: 요일 7열 × 시간 24행 표. 칠한 칸 = 열림, 나머지 = 차단. 빈 표 = 24시간 차단.
	- 드래그 또는 shift-클릭으로 여러 칸을 한 번에 칠하거나 지운다.
- 기존 묶음: 하단 "묶음 삭제". 모든 변경은 즉시 저장하며 적용 버튼은 없다.
- 새 묶음: 하단 "추가". 누르면 묶음이 생기고 시트가 닫힌다. 제목이 비어 있으면 첫 주소의 호스트를 제목으로 쓴다.

### 안내 페이지 (차단 시 브라우저 화면)

- 엔진이 돌려주는 HTML 한 장.
- 내용: "정신 차리고 중요한 일에 집중하세요." · 묶음 제목 · 다음 열림 시각(있을 때) · 막힌 호스트.
- 다음 열림 시각: 시간표에서 지금 이후 첫 열린 칸. 7일 안에 없으면 그 줄은 생략.

## 규칙 파일 (앱↔엔진 계약)

- 위치: `~/Library/Application Support/Impel Down/rules.json`. 앱이 처음 켜질 때 빈 규칙으로 만든다.
- 쓰기: 앱이 임시 파일에 쓴 뒤 이름을 바꿔 원자적으로 교체한다.
- 읽기: 엔진이 1초마다 수정 시각을 보고 바뀌면 다시 읽는다. 파싱에 실패하면 직전 규칙을 유지한다.
- 스키마 (version 1):

```json
{
  "version": 1,
  "groups": [
    {
      "id": "8f1c0a4e-…",
      "title": "커뮤니티",
      "addresses": ["community.example", "video.example/shorts"],
      "open": { "sat": [20, 21, 22], "sun": [20, 21, 22] }
    }
  ]
}
```

- `id`는 UUID. `open`의 키는 `mon`…`sun`, 값은 0–23 정수 배열 (그 시부터 한 시간 열림).
	- 키가 없거나 배열이 비어 있으면 그 요일은 하루 종일 차단.
- 주소의 뜻 (앱의 붙여넣기 정리와 엔진의 매칭이 같은 규칙):
	- `host` — 그 도메인과 모든 서브도메인. 점 경계에서만 (`example.com`은 `a.example.com`에 걸리고 `notexample.com`엔 안 걸린다). 대소문자 무시.
	- `host/path` — 위 호스트 조건 + 요청 경로가 `/path`와 같거나 `/path/`로 시작. 쿼리는 무시.
- 시간의 뜻: 맥 로컬 시간. 판정은 요청 시각 기준.
- 판정: 요청이 어느 묶음의 어느 주소에든 걸리고 그 묶음이 지금 닫혀 있으면 차단.
	- 여러 묶음에 걸리면 하나라도 닫혀 있으면 차단. 안내 페이지엔 차단한 묶음(여럿이면 첫째)의 제목과 다음 열림 시각.

## 엔진

### 프록시

- mitmproxy를 `127.0.0.1`의 고정 포트(기본 8899)에서 일반 HTTP(S) 프록시로 돌린다. 애드온 하나가 판정을 맡는다.
- 복호화 범위: HTTPS 연결의 목적지 호스트가 규칙의 어느 주소 호스트에든 걸리면 복호화하고, 아니면 손대지 않고 터널로 통과시킨다.
	- 호스트만 등록한 주소(통째)도 복호화한다. 안내 페이지를 돌려주기 위해서다.
- 차단 응답: 상위 서버에 연결하지 않고 `403` + 안내 HTML을 돌려준다. 평문 HTTP 요청도 같은 판정.
- 열린 시간이거나 규칙에 없으면 그대로 통과.

### 시스템 프록시 유지

- 엔진이 30초마다 모든 네트워크 서비스의 HTTP·HTTPS 프록시 설정을 확인한다.
	- 비어 있거나 다른 값이면 `127.0.0.1:포트`로 다시 잡는다. 새로 생긴 서비스(VPN 등)도 같은 처리.

### hosts 관리

- 24시간 차단(시간표가 빈) 묶음에서 호스트만 등록한 주소를 `/etc/hosts`의 전용 블록(`# impel-down` … `# /impel-down`)에 `127.0.0.1 host`로 미러한다.
	- 규칙이 바뀔 때마다 블록을 통째로 다시 쓴다. 블록 밖은 건드리지 않는다.
	- hosts는 서브도메인을 못 잡으므로 등록된 문자열 그대로와 `www.` 변형만 쓴다.
	- 호스트명 문법(`[a-z0-9.-]`, 점 경계)을 통과한 값만 쓴다. 경로가 있는 주소나 그 외 문자열은 쓰지 않는다.
- 엔진이 죽어 있는 동안에도 이 사이트들은 막힌다.

### 실행 주체와 권한

- 엔진은 root 권한 LaunchDaemon (`/Library/LaunchDaemons/com.impel-down.engine.plist`). 시스템 프록시 설정과 hosts 쓰기에 관리자 권한이 필요하다.
- 엔진이 실행하는 파일(mitmproxy 실행 파일·애드온·스크립트)은 전부 root 소유 디렉토리 `/Library/Application Support/Impel Down/`에 둔다.
	- 사용자 권한으로 고칠 수 있는 파일을 root가 실행하지 않는다.
- 규칙 파일은 사용자 권한 파일이므로 데이터로만 읽는다. JSON 파싱 → 스키마 검증 → 위 호스트명 검증을 거친 값만 쓴다.
	- 규칙 파일의 절대 경로는 설치 스크립트가 설치한 사용자의 홈으로 plist에 박는다.
- mitmproxy 인증서와 개인 키는 root의 설정 디렉토리에 둔다.

## 설치·제거

- 엔진 런타임: mitmproxy 공식 macOS 독립 실행 파일을 `/Library/Application Support/Impel Down/mitmproxy/`에 둔다. Homebrew·시스템 Python에 의존하지 않는다.
- `engine/install.sh` (sudo 한 번):
	1. 위 디렉토리 생성, 실행 파일·애드온 복사, root 소유.
	2. LaunchDaemon plist 설치 후 `launchctl bootstrap`.
	3. 엔진 첫 실행이 만든 인증서를 시스템 키체인에 신뢰 루트로 등록.
	4. 시스템 프록시는 엔진의 유지 루프가 첫 주기에 잡는다.
- `engine/uninstall.sh`: 프록시 설정 해제 → 인증서 신뢰 해제 → 서비스 `bootout`·plist 제거 → hosts 블록 제거 → 디렉토리 제거. 규칙 파일은 남긴다.
- 앱: Xcode로 빌드해 `/Applications`에. 로그인 항목 등록은 앱이 첫 실행 때 한다.

## 테스트

- 엔진 단위 (pytest): 주소 매칭(서브도메인 점 경계·경로 세그먼트 경계·쿼리 무시·대소문자) · 시간표 판정과 다음 열림 계산(주 경계 넘김 포함) · 규칙 파일 재로드(수정 시각·파싱 실패 시 유지) · hosts 블록 생성(검증 통과 값만) · 안내 HTML 렌더.
- 앱 단위 (XCTest): 붙여넣기 정리 · 카드 상태 문구와 시간표 요약 · 규칙 파일 직렬화.
- 계약: 견본 `rules.json` 하나를 `docs/fixtures/`에 두고 앱·엔진 테스트가 같이 읽는다. 앱이 쓴 파일을 엔진 파서가 읽어 같은 값이 나와야 통과.
- 통합: 테스트 포트에 엔진을 띄우고 curl(`--proxy`, 인증서 지정)로 셋을 확인한다.
	- 규칙 밖 호스트 통과 · 규칙 호스트 403 + 안내 HTML · 열린 시간 통과.
- 픽스처 값은 전부 placeholder(`community.example` 등). 실제 사이트 목록은 repo에 두지 않는다.

## 구현 전 실측 (spike)

코드 전에 실제 기기에서 잰다. 결과에 따라 위 설계를 고친다.

- Safari가 시스템 프록시를 타고 안내 페이지를 표시하는지. iCloud Private Relay 켜짐·꺼짐 각각.
- Chrome이 프록시 설정 상태에서 QUIC(UDP)로 프록시를 건너뛰지 않는지.
- root LaunchDaemon에서 `networksetup`이 인증 창 없이 프록시를 바꾸는지.
- mitmproxy 애드온에서 연결별로 복호화·터널 통과를 고를 수 있는지 (`tls_clienthello` 훅).
- mitmproxy 독립 실행 파일이 root LaunchDaemon에서 정상 기동하는지.

## 알려진 한계

- 페이지 안에서 화면을 갈아끼우는 사이트(동영상 사이트 등)는 경로 주소가 직접 진입·새로고침 때만 잡힌다. 그런 사이트는 호스트를 통째로 등록한다.
- 시간표는 1시간 단위.

## 범위 밖 (v2 후보)

- 사이트별 내부 요청 주소 차단.
- 30분 단위 시간표.
